# Add ForgeKit as a second local package

GitX will add `ForgeKit` as a second local Swift package beside `GitXCore`. `GitXCore` continues to own GitX's existing Foundation-only Git and presentation decisions; Forge integration has a distinct dependency, caching, authentication, and future multi-Forge boundary and therefore does not belong in that package or directly in the application target.

Milestone 0 establishes the package with provider-neutral Forge identity, remote detection, destination validation, and link construction. Milestone 1 adds authenticated transport, persistence, and the GitHub adapter; later milestones extend the same boundary rather than migrating temporary application-layer link logic. Through Milestone 3, the adapter performs authenticated native API operations only against GitHub.com. GitHub Enterprise Server remotes retain provider-aware identity, links, and browser routing without authenticated native API surfaces.

The package will contain at least two targets:

- `ForgeKit`, which owns provider-neutral identities, value types, capability protocols, rollup policies, cache records, pagination, refresh policy, and mutation results; and
- `GitHubForgeAdapter`, which depends on `ForgeKit`, Apollo iOS, and the targeted REST transport needed for authentication, Actions-adjacent data, downloads, or GraphQL gaps.

The package pins Apollo iOS exactly at 2.3.0 and checks its resolved revision into the workspace. Dependency upgrades are explicit reviewed changes that regenerate GraphQL sources and rerun the complete verification matrix; SwiftPM does not select newer compatible releases implicitly.

Apollo code generation and generated GraphQL types remain implementation details of `GitHubForgeAdapter`. The adapter maps every GraphQL and REST result into `ForgeKit` values before exposing it to GitX. The application composes capabilities at its existing composition root and must not import Apollo modules or use generated GraphQL types.

Apollo's normalized cache is memory-only. Persistent public and per-account Forge snapshots, REST results, Attention state, and drafts use one `ForgeKit`-owned system-SQLite store without adding a SQLite wrapper dependency. Fetched API snapshots and derived render data form a disposable cache governed by the 250 MB global LRU. Drafts, watched-repository choices, and seen markers are durable database records outside that eviction budget and are deleted only by their explicit retention, discard, or account-removal rules. Forge Repository Bindings remain in Repository View State and polling preferences remain in Application Preferences; both are likewise outside cache eviction.

The refresh coordinator enforces server-reported rate-limit cooldowns per Credential. When GitHub throttles a Credential, every background poll for that Forge Account pauses until the supplied retry or reset time instead of allowing independent repositories to keep consuming the same account-wide limit. Anonymous public requests share one app-wide remaining-budget counter and cooldown rather than maintaining misleading per-repository allowances. During a server-provided cooldown, manual API refresh and every Forge mutation using the affected Credential are disabled rather than allowed to override the retry window; the UI preserves drafts and local state and offers **Open on GitHub**. The repository status bar shows **Rate Limited**, the remaining cooldown time, and the age of its cached Forge data. If the status bar is hidden, the Forge toolbar control does not mirror the rate-limit warning or countdown; each disabled Forge action instead exposes **Rate limited until [time]** in its tooltip or disabled-state help. GitX does not offer rebinding the repository to another Forge Account as a cooldown bypass. Cooldown deadlines are session-local and are discarded when GitX quits; a relaunched app may attempt requests normally until GitHub reports another throttle.

Schema changes are transactional. GitX may discard and rebuild fetched snapshots, but a corrupt database or failed durable-state migration is copied aside for diagnostics and never silently reset. A copied-aside recovery database is excluded from system backups and automatically deleted after 30 days. The failure-time recovery UI lists retained copies and provides **Reveal in Finder** and a single-step **Delete Now** action with no additional confirmation; retained copies do not remain exposed in Application Preferences after that UI is dismissed. **Delete Now** permanently removes the recovery file rather than moving it to the Trash, without claiming secure erasure beyond normal filesystem deletion. The surrounding copy states that deletion may remove the last copy of unrecovered drafts. GitX attempts durable-record recovery and offers Retry, an explicitly destructive Reset Forge Data action, and **Not Now**. **Reset Forge Data** also clears the app-wide trusted external-link origin list even though that list is stored in Application Preferences. **Not Now** keeps core local Git features available while disabling Forge features for the rest of the current session. The repository status bar then shows a persistent **Forge Unavailable** state whose **Details** action reopens recovery during the same session. If the status bar is hidden, the existing Forge toolbar control mirrors the failure with a warning badge and the same **Details** action; GitX does not force the bar visible. On the next launch GitX retries opening and recovering the Forge database automatically, presenting the recovery UI again only if that attempt still fails. GitX does not provide a draft-export feature.

The boundary is enforced in local and CI static verification. Separate Swift targets provide compile-time isolation; a checked-in Python boundary checker rejects Apollo imports outside the adapter and generated-source locations; and an exported-symbol check fails if Apollo or generated types appear in public APIs. Focused Python tests cover the enforcement rules. GitX will extend its existing dependency-free boundary-checking pattern rather than add Semgrep.
