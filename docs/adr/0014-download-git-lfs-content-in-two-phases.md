# Download Git LFS content in two phases

GitX reads Git LFS repositories passively and downloads LFS Objects only when asked. History, staging, Quick Look export and Flow read blobs through `git show` and `git cat-file`, which never run the smudge filter, so an LFS Pointer reaches GitX as pointer text. GitX recognizes a pointer only when the path's `filter` attribute is `lfs` and the blob is a strict spec-v1 pointer under 1024 bytes. If the matching object is in the local store, and its size and SHA-256 digest match, GitX renders the object, up to a 64 MiB preview limit. Otherwise it shows a Not Downloaded placeholder. Exporting a file that is not downloaded fails with an explicit error; GitX never writes pointer bytes as the file's content. Flow analyzes a stored object as the file's source and leaves a file that is not downloaded out of the comparison, logging why, because FlowDelta's revision comparison has no place for a per-file note. The status bar's scan is local too: `ls-files` with an attribute pathspec, `cat-file` batches, `lstat`, and `git lfs version` while the tool's state is unknown. It never contacts a remote.

A download is explicit and covers only the current checkout. It runs as two commands with different lifetimes:

1. `git lfs fetch` writes only the local object store, so GitX treats it as a read. It has no deadline, but a stall watchdog stops it after ten minutes without progress. Cancel, closing the window, and Quit all terminate it; the checkout is unchanged.
2. `git lfs checkout` rewrites worktree files and the index, so it is a local mutation under ADR 0009. It waits for mutation admission through the index writer and, once started, runs to completion; its sheet says “Finishing…” and disables Cancel. If Quit has sealed admission, the objects stay in the store and GitX reports that the checkout was deferred. Downloading again finishes it without fetching anything twice.

Paths are passed to git-lfs as anchored, escaped patterns. git-lfs splits `--include` on commas, so GitX refuses to download a path containing a comma, newline or NUL by itself, and offers Download All instead. GitX requires git-lfs 3.0 or later. GitX's own checkout, reset and stash commands still run whatever filters the repository configures; this decision does not change them.
