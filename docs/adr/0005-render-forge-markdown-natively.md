# Render Forge Markdown natively with swift-markdown

GitX will parse Forge-authored Markdown with `swift-markdown`, sanitize it into a GitX-owned document model, and render that model through native AppKit views. The renderer will never accept an unsanitized syntax tree. This extends ADR-0001's native-rendering direction to Pull Requests, Issues, comments, and reviews while retaining GitHub-flavored Markdown structure and offline rendering; Foundation's narrower attributed-string parser and server-rendered HTML were rejected because they respectively lose important structure or enlarge the untrusted-HTML and WebKit-adjacent surface.

The package pins `swift-markdown` exactly at 0.8.0 and checks its resolved revision into the workspace. Upgrades are explicit reviewed changes that rerun sanitizer fixtures, native-renderer tests, dependency-boundary checks, and the complete verification matrix.

## Sanitization contract

Forge Markdown is untrusted input. The sanitizer may emit only:

- text, paragraphs, headings, block quotes, lists, task-list state, tables, thematic breaks, and line breaks;
- emphasis, strong emphasis, strikethrough, inline code, and fenced code blocks;
- links whose destinations pass the URL policy below; and
- images as inert alt text and a placeholder, never as automatically loaded content.

Raw HTML, custom directives, embedded media, forms, scripts, style data, and unknown nodes are discarded as structure and rendered only as inert text when preserving their source helps comprehension. They are never interpreted as AppKit view descriptions, attributed-string markup, or HTML.

Link destinations must be absolute `https` URLs, `mailto` URLs, or relative Forge references that resolve within the bound Forge Repository. GitX parses both the configured Forge base and the resolved destination as URLs; it never compares origins with string prefixes or suffixes. A Forge origin is valid only when it uses `https`, has a normalized host, contains no userinfo, and has a valid effective port. Origin comparison requires the same normalized host and effective port, treating an omitted HTTPS port as 443. A non-default port is accepted only when the configured Forge origin explicitly uses that same port.

Relative references in Pull Request, Issue, review, and comment Markdown resolve from the bound repository root at its default branch. Relative references in file-backed Markdown resolve from the displayed file's directory at the displayed revision. Resolution must produce an `https` URL on the exact configured Forge origin and within the bound repository; path components and revisions are percent-encoded as URL components rather than interpolated into raw URL strings. Protocol-relative forms, malformed URLs, credentials in authority components, other schemes, local-file paths, and relative paths that escape the repository render as plain text. Absolute `https` links to other origins and valid `mailto` links remain allowed, but they do not qualify as relative Forge references. A fragment-only link scrolls to the matching heading in the currently rendered native document; it never opens another application or causes network access. Heading identifiers follow GitHub-compatible slug generation, including duplicate-heading suffixes, with compatibility fixtures for punctuation, Unicode, whitespace, and duplicates.

A recognized Pull Request, Issue, commit, or file link within the bound repository is sent through GitX's validated native destination router when that destination is supported. Every natively routed Forge link also offers **Open in Browser** from its context menu as an explicit escape hatch. Unsupported or unrecognized routes, links to other repositories, other allowed `https` links, and `mailto` links open through the system browser or mail application. Before opening an `https` destination whose normalized origin differs from the configured Forge origin, GitX presents a confirmation sheet that displays the complete normalized URL. For an internationalized hostname, the sheet shows both its display form and its ASCII/Punycode form. The sheet offers **Always Allow Links to This Host**; accepted entries persist app-wide and can be reviewed or removed in Application Preferences. Each entry is scoped to an exact normalized HTTPS origin—scheme, normalized host, and effective port—with no wildcard, subdomain, parent-domain, or alternate-port inheritance. **Reset Forge Data** clears the entire trusted-origin list; removing an individual Forge Account does not. Before opening a `mailto` destination, GitX always presents a confirmation sheet showing its decoded To, CC, and BCC recipients, decoded subject, and whether it contains a prefilled body. Mail confirmation has no persistent recipient or domain bypass. Links act only after an explicit user action. GitX does not prefetch destinations, generate remote previews, open them in an embedded browser, automatically fetch missing Git objects, or automatically clone repositories.

Images never trigger network or local-file access during parsing or rendering. A future explicit image-loading feature must use a separately reviewed network boundary, allow only `https`, prevent credential forwarding to unrelated hosts, enforce response size and media-type limits, and preserve the inert placeholder on failure.

This Markdown rule does not cover structured account and author avatar URLs returned in GitHub API identity fields. GitX may fetch those only from a checked-in exact GitHub avatar-host allowlist through a separate credential-free, cookie-free, referrer-free client that revalidates redirects, enforces byte, decoded-pixel, and media-type limits, and falls back to a native initials badge. An avatar URL embedded in Markdown never qualifies for this exception.

Avatar decoding is static: PNG, JPEG, and size-bounded GIF or WebP responses use only their first raster frame, while animation, SVG, HTML, and MIME/content mismatches fall back to initials. A shared credential-free avatar LRU has a 25 MB sub-cap within the 250 MB global Forge cache budget. The application-wide Load Avatars preference defaults on; turning it off cancels requests, clears that sub-cache, and immediately replaces remote images with initials.
